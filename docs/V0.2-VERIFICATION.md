# v0.2 verification — smoke-test re-walk

**Date:** 2026-05-30
**Scope:** Re-walk of [`SMOKE-TEST-PROTOCOL.md`](SMOKE-TEST-PROTOCOL.md) against the post-v0.2-docs-sync command files. The protocol document was authored alongside the v0.2 spec changes and already encodes the post-v0.2 PASS / FAIL expectations; this verification confirms the command files actually carry the load-bearing text the protocol promises.

This is a **spec-level** verification, not a runtime smoke test. It asserts the spec is now sufficient to PASS the protocol's signals and that the FAIL-mode prevention now has a runtime mechanism rather than honour-system text. A live behavioural smoke test is a separate exercise.

---

## Method

For each of the six modes I re-read the command file and the matching SKILL.md section, then walked the protocol's PASS / FAIL signals one-by-one. I treated a PASS signal as *satisfied* when the spec text concretely binds the LLM to produce it (verbatim block, imperative "must", explicit step number). I treated a FAIL signal as *prevented* when the spec text either forbids the behaviour or installs an architectural mechanism (file read, log append, header counter) that displaces the honour-system version.

I also ran two structural checks: a grep across `commands/` and `art-ideation/SKILL.md` for the four deprecated agents by name, and an `ls` on the suite-root `agents/` symlink path. I then re-ran `mkdocs build --strict --clean` as a wiki integrity check.

## Residual gaps (honest)

1. **This is a spec-level verification, not a runtime smoke test.** The PASS / FAIL signals here measure whether the spec text now concretely binds the behaviour at the prompt level. A behavioural smoke test in a live Claude Code session — actually running each of the six prompts in `SMOKE-TEST-PROTOCOL.md` and observing real outputs — is the next exercise and would catch the gap between *spec-binding* and *runtime-honouring* (e.g. cases where Claude reads the IRON RULE but drifts under conversational pressure).

2. **Persona-collapse detector remains SOFT at v0.1.** `commands/rehearsal.md` line 41 acknowledges this explicitly: "qualitative check at v0.1, not a measured similarity score; subtle collapse may fail silently and an external reader remains the corrective." Not a v0.2 regression — it was scoped to v0.3 by design — but it is the one rehearsal-mode signal that is not HARD.

3. **Concession Threshold Protocol relies on file-import inheritance.** The protocol is implemented in `art-ideation/agents/devils_advocate_agent.md` and inherited rather than re-asserted in `commands/rehearsal.md`. SMOKE-TEST-PROTOCOL.md line 214 notes this dependency. In practice the command file does name "Concession Threshold Protocol" (line 37) and "Devil's Advocate" by name, so Claude's file-import reflexes should activate the agent; this has not been runtime-verified.

4. **Filesystem dependencies untested at runtime.** The two v0.2 architectural upgrades (rehearsal-log + project-file) both depend on Claude actually executing the file-system operations the spec describes. The spec includes a graceful-fallback branch in both modes, but neither the happy path nor the fallback path has been runtime-exercised.

5. **One Bash-tool dependency.** The `mkdocs build --strict --clean` run emits the upstream "MkDocs 2.0 warning" banner from Material-for-MkDocs. This is benign — it is an upstream project notice, not a build error — but downstream CI that grep-fails on "Warning" output should be configured to ignore this banner.

## Recommendation — is the plugin ready for an honest "v0.2 ready" tag?

**Yes, with three caveats.**

The four v0.2 commitments named in `docs/V0.2-DESIGN-DECISIONS.md` and tested by `SMOKE-TEST-PROTOCOL.md` all have HARD-binding spec text now:
- (a) rehearsal friction via `~/.art-project/rehearsal-log.jsonl` — HARD-bound at `commands/rehearsal.md` lines 43-60.
- (b) full-mode persistence via `~/.art-project/projects/<codename>/project.md` — HARD-bound at `commands/ideate.md` lines 26-69.
- (c) socratic intent-detection HARD — bound at `commands/socratic.md` lines 10-16; DHI demoted to `rehearsal`-only sub-check.
- (d) deprecated agents archived — confirmed structurally (deprecated folder exists; no command-file references; suite-root `agents/` absent).

The wiki builds clean under `--strict`. The spec is sufficient to honour all PASS signals across all six modes (35/35 PASS signals satisfied) and to prevent the load-bearing FAIL signals (33/34 FAIL signals prevented; the one remaining SOFT signal is rehearsal's persona-collapse detector, scoped to v0.3 by design and disclosed honestly in the spec).

**Caveats:**
1. The tag should be **`v0.2-spec` or `v0.2-docs-sync`** rather than a bare `v0.2`, to make explicit that this is a docs-and-spec milestone — not a runtime-verified behavioural release. The honest framing is *the plugin's spec is now sufficient to enforce the v0.2 commitments; whether Claude honours that spec consistently at runtime is the next exercise.*
2. A live behavioural smoke test in a real Claude Code session should be queued as the immediate next step. The exercise is well-scoped in `SMOKE-TEST-PROTOCOL.md` and should take ~30 minutes.
3. The persona-collapse detector should be tagged as v0.3 scope in the issue tracker so the SOFT status is tracked, not forgotten.

If the maintainer wants a bare `v0.2` tag for marketplace cleanliness, that is defensible — but the release notes should name caveats (1)-(3) explicitly. The plugin is *spec-ready*; *behaviourally-ready* requires the runtime smoke test pass.
