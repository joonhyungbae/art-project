# art-project v0.2 — Four Design Decisions

**Date:** 2026-05-30
**Inputs:** Runtime-Readiness Audit 2026-05-30 (`docs/PLUGIN-RUNTIME-READINESS-AUDIT.md`); v0.1 commands (`commands/rehearsal.md`, `commands/ideate.md`, `commands/socratic.md`); skill spec (`art-ideation/SKILL.md:147-170, 218-237`).
**Method:** Three-voice editorial debate. Decisions are made here, not delegated to the user.

The four open questions:

- (a) Rehearsal session-history mechanism — build a real tracker, or accept honour-system?
- (b) `full` mode cross-session filesystem persistence — build it, or stay artist-managed?
- (c) Two SOFT IRON rules (Dialogue Health Indicator every 5 turns; intent detection every 3 turns) — operationalize, or remove from the IRON-rule registry?
- (d) Four drift agents (`research_question_agent`, `source_verification_agent`, `synthesis_agent`, `monitoring_agent`) — delete, rewrite, or archive?

---

## Voice 1 — Maintainer / Scope-discipline

**(a) Rehearsal session-history.** Accept the honour-system. The plugin is for a single working artist preparing an AHCI submission to *Digital Creativity*; the rehearsal-friction warning at `commands/rehearsal.md:41` is *for the artist*, not for a third party who needs auditable enforcement. The honour-system isn't a documentation lie — it's `commands/rehearsal.md:41` saying out loud that the plugin asks. That sentence is in the command file. Reviewers reading the paper see "honour-system at v0.1" written into the artifact they're reviewing. Building a `~/.art-project/rehearsals.jsonl` for one user, where that user is also the only person who would care whether it logged correctly, is the exact kind of premature infrastructure that delays shipping. Keep it.

**(b) `full` mode persistence.** Stay artist-managed. `commands/ideate.md:28` is explicit: *"the artist designates a filename… the artist is responsible."* That is not a placeholder, it's the design. The plugin is CC-BY-NC and lives inside `~/.claude/`; auto-creating `~/.art-project/projects/[codename]/` directories on the user's filesystem makes the plugin do filesystem work the artist hasn't asked for, in a path nobody's git-tracking, with no migration story when the artist moves machines. The current model — artist names the file, pastes it back — survives every machine change, every reinstall, every "let me copy this to my collaborator". That portability is worth more than the friction it costs.

**(c) Two SOFT IRON rules.** Remove from the IRON-rule registry; downgrade to "design principles" in SKILL.md. The audit (`docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:73-74`) is right that #15 and #16 are SOFT — they presuppose a runtime counter the plugin doesn't have and Claude can't reliably maintain. Calling them IRON rules when they aren't enforceable is the documentation lie Voice 2 wants to fix in the other direction; the cheap fix is to stop calling them IRON. The cadence numbers (every 5 turns / every 3 turns) were inherited from the academic-research-skills pipeline where they were also aspirational. Inheritance is not validation.

**(d) Drift agents.** Delete entirely. `docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:106` confirms zero commands dispatch any agent; the deprecated banners (`art-ideation/SKILL.md:230-233`) tell readers the agents are dead. Keeping them around as "historical archive" is cognitive load — every future reader has to figure out which agents are live and which are vestigial. Delete the four, update `SKILL.md:218-237` to a four-row table, drop the symlink at `agents/synthesis_agent.md`. Diff-traceability is what `git log` is for.

## Voice 2 — Architect / Real-mechanism

**(a) Rehearsal session-history.** Build it. The empirical claim in the *Digital Creativity* submission validates one property of one mode: zero ex-nihilo fabrication in `brief` reconstruction. The plugin's rehearsal section makes a *different* claim — "architectural friction against repeated use" (`commands/rehearsal.md:2`). When the implementation is "ask the artist", the artifact is asking-the-artist, not friction-against-repeated-use. Those are different things. The spec promises one; the runtime delivers the other. That is the documentation lie. A flat append-only log at a stable path — one line per rehearsal invocation: `ISO-8601 timestamp | concept-slug` — is roughly 30 lines of skill prompt and one new shared reference. The plugin reads the last 14 days at rehearsal entry, counts entries matching the concept-slug the artist supplies, and the warning fires *automatically* at N≥2. That is a real mechanism. It is also small.

**(b) `full` mode persistence.** Build it. The cross-session continuity claim in `art-ideation/SKILL.md:160` is rule #10 of the IRON list. An IRON rule whose implementation is "the artist copy-pastes a file each session" is an IRON rule resting on user discipline the spec elsewhere is careful never to assume. The audit's Phase 5 entry (`docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:119`) names this exactly: *"verification gap"*. Decide a concrete schema for `~/.art-project/projects/[codename]/project.md`, give it a template, write the read/append logic into the skill prompt for `ideate` mode. Two days of work; the cross-session claim then survives a smoke test instead of a sympathetic reader.

**(c) Two SOFT IRON rules.** Operationalize. Removing rules from the IRON list because they're hard is the slope every safety regime slides down. Intent detection every 3 turns is implementable as a per-turn classifier prompt embedded in `commands/socratic.md` — three lines of prompt instruction Claude follows reliably (it follows the *4*-step Concession Threshold Protocol in `devils_advocate_agent.md:28-30` reliably; this is the same kind of instruction). The Dialogue Health Indicator every 5 turns is the same shape. Bind them into the relevant command-file prompts; remove them from the global "inherited safety machinery" list (`SKILL.md:164-170`) and put them where they fire. Done.

**(d) Drift agents.** Rewrite. The audit notes the four drift agents reference at least four files that don't exist (`docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:25-28`). Deletion loses the dependency graph the v0.2 synthesis spec §7 (cited at `art-ideation/SKILL.md:237`) treats as the rewrite roadmap. The *work* of rewriting `synthesis_agent.md` into v0.2 brief-integration semantics is what forces clarity about what `brief` mode's chair-synthesis actually does. Skipping that work to "save cognitive load" exports the unclarity to v0.3.

## Voice 3 — User-experience / Artist-in-the-loop

**(a) Rehearsal session-history.** Build it, but lightly. The artist's actual experience: it's been two weeks, they vaguely remember rehearsing this concept once, maybe twice — was the second time with a different framing? They don't want to be the source of truth for the warning. They want the warning to fire when it should. The honour-system at `commands/rehearsal.md:41` puts the burden on the artist's memory; from the inside that's not "the artist owns the warning", it's "the artist has to remember to be warned". A one-line append-log the plugin reads — not enforced, just *consulted* — converts "do you remember?" into "the log says you rehearsed this on the 12th and the 19th, that's two in 14 days, here's the friction prompt". The warning still goes to the artist, the artist still decides whether to proceed. The plugin remembering is helpful; the plugin enforcing would not be.

**(b) `full` mode persistence.** Build it. This is where the artist-managed model genuinely breaks. The `commands/ideate.md:10-22` evolution table — eight sessions over three months — only happens if the artist pastes the file back every time. By session six, on a deadline, the artist will skip the paste, or paste only the last session, or paste a stale copy. The cross-session continuity claim then becomes vapor. Voice 1's portability argument is real but solvable: the plugin writes to `~/.art-project/projects/[codename]/project.md`, and that file is just a markdown file in a known location the artist can git-commit, sync, copy. Portability is preserved; the artist no longer has to remember to paste. The plugin reads the file at session start and writes the session log at session end — the artist sees what was written, can edit, can refuse.

**(c) Two SOFT IRON rules.** Operationalize the intent-detection one; demote the Dialogue Health Indicator. From the artist's seat, intent detection matters: socratic mode is where it's easy for Claude to slide into "ready to summarize?" by turn three, and the artist's pain there is real. Bind intent detection into `commands/socratic.md:8` with concrete per-turn behaviour. The Dialogue Health Indicator (#15) is more diffuse — "agreement spirals" is hard to surface usefully every 5 turns without becoming nagging. Demote it to a Devil's Advocate sub-check inside rehearsal mode, where dialogue health actually has stakes.

**(d) Drift agents.** Archive in a `deprecated/` subdirectory, then delete in v0.3. The artist-user doesn't read the agents. The reviewer-user (Voice 1's concern about cognitive load) reads them if the audit points there. Move the four drift agents to `art-ideation/agents/deprecated/`, leave a one-line stub in the parent directory pointing at the archive, and update `SKILL.md:218-237` to a clean v0.2 table. Six months from now the diff-traceability matters less than the table cleanliness.

## Synthesis — Decisions

### (a) Rehearsal session-history: **build a minimal log; decision dominated by Voice 3, Voice 1's red line honoured.**

Add an append-only log at `~/.art-project/rehearsal-log.jsonl`, one record per rehearsal invocation: `{timestamp, concept_slug, session_id}`. The skill prompt for rehearsal mode (the relevant binding sits in `commands/rehearsal.md:41`) is updated to:

1. At rehearsal entry, ask the artist for the concept-slug.
2. Read the log; count records matching the slug in the last 14 days.
3. If N≥2, emit the existing friction warning verbatim.
4. After the artist confirms proceed, append a new record.
5. If the log file is absent or unreadable, fall back to the current ask-the-artist honour-system and say so explicitly in the warning ("log unavailable; relying on your self-report").

Voice 1's red line — *the artist still owns the decision, the warning is not punitive* — is honoured because the warning is consultative, not blocking. Voice 2's red line — *the implementation has to match the spec language* — is honoured because the warning now genuinely fires from runtime state, not from artist memory. Voice 3's framing dominates: the plugin *remembers* and *prompts*, it does not *enforce*.

Update `commands/rehearsal.md:41` to drop "honour-system at v0.1" and replace with the consultative-log description. Update IRON-rule classification of #11 (`docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:69`) from UNENFORCED to HARD.

### (b) `full` mode persistence: **build it; decision dominated by Voice 3 with Voice 2 concurring, Voice 1's portability red line honoured.**

Implement minimal filesystem persistence. The plugin manages `~/.art-project/projects/[codename]/project.md` (single markdown file per project, no directory tree). The skill prompt for `full` mode (`commands/ideate.md:26-44`) is updated to:

1. New project: ask for codename, create `~/.art-project/projects/[codename]/project.md` with the header template, append the first session block.
2. Existing project: read `~/.art-project/projects/[codename]/project.md`, summarize last 1–2 sessions, ask where to continue.
3. End-of-session: append the session checkpoint block to the project file. Surface the diff to the artist before writing.
4. The file is plain markdown the artist can git-commit, edit, move, copy.

Voice 1's portability red line is honoured because the file is plain markdown in a known location, fully owned by the artist post-write. No proprietary format, no SQLite, no schema migration. Voice 3's UX argument carries: the artist no longer has to remember to paste, which is the failure mode that turns the cross-session claim into vapor.

Update `commands/ideate.md:28` ("v0.1 honesty note") — replace with the v0.2 mechanism description. Update IRON rule #14 (`docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:72`) from SOFT to HARD.

### (c) Two SOFT IRON rules: **operationalize intent detection; demote Dialogue Health Indicator. Decision dominated by Voice 3, Voice 1's "stop calling things IRON if they aren't" red line honoured.**

- **Intent detection (#16):** Bind into `commands/socratic.md` as a per-turn instruction: *"Before each response, classify the artist's most recent turn as exploratory (still surfacing material) or goal-oriented (asking for a deliverable). If exploratory, the no-auto-convergence rule remains active. If goal-oriented for two consecutive turns, ask once whether the artist wants to move toward a Concept Pull Map; do not push."* That is a concrete per-turn behaviour Claude can execute. Promote #16 from SOFT to HARD.
- **Dialogue Health Indicator (#15):** Demote from IRON-rule registry to a Devil's Advocate sub-heuristic inside `rehearsal` mode. Bind into `commands/rehearsal.md` as part of the DA persona: *"If, across the four-persona pass, three or more personas raise concerns of the same kind, surface that pattern in the DA turn — this is the dialogue-health signal in rehearsal context."* It overlaps with the persona-collapse detector (`commands/rehearsal.md:39`), which is the honest place for it. Remove #15 from the IRON-rule list in `SKILL.md:147-162` and from `docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:73`.

Voice 1's red line — *stop calling things IRON if they don't fire* — is honoured by demoting #15. Voice 2's red line — *don't drop safety rules because they're hard* — is honoured by keeping intent detection as a HARD rule rather than dropping both.

### (d) Drift agents: **archive in `art-ideation/agents/deprecated/`; rewrite plan deferred to v0.3. Decision dominated by Voice 3, Voice 1's cognitive-load red line honoured.**

Move the four drift agents (`research_question_agent.md`, `source_verification_agent.md`, `synthesis_agent.md`, `monitoring_agent.md`) into `art-ideation/agents/deprecated/`. Drop the suite-root symlink at `agents/synthesis_agent.md` (it currently points into the drift set and no command dispatches it). Update `art-ideation/SKILL.md:218-237` to a clean four-row table listing only the v0.2-aligned agents (`socratic_mentor_agent`, `bibliography_agent`, `devils_advocate_agent`, `editor_in_chief_agent`), with a single sentence below the table: *"Four v0.1-paper-era agents are archived in `agents/deprecated/`; see `docs/PLUGIN-RUNTIME-READINESS-AUDIT.md` Phase 4."*

Voice 1's red line — *don't make readers parse dead code* — is honoured because the main `agents/` directory becomes the v0.2 set only; the deprecated subdirectory has a README explaining "archived, do not invoke". Voice 2's red line — *don't lose the rewrite roadmap* — is honoured because the files are still on disk, the audit's Phase 4 still names them, and v0.3 can either rewrite or delete with full provenance. Voice 3's archive-then-delete pacing is the operative compromise: archiving costs almost nothing and resolves the runtime risk; deletion can happen in v0.3 once the v0.2 rewrite either does or does not need them.

The four missing files the drift agents reference (`art_research_evidence_model.md`, `word_count_conventions.md`, `acm_reference_format.md`, `literature_monitoring_strategies.md`, per `docs/PLUGIN-RUNTIME-READINESS-AUDIT.md:25-28`) stay missing; the archive header notes them as part of the historical state, not a v0.2 backlog.

Total estimate: roughly one working week of focused work, less if items 1 and 2 are batched into a single sitting. None of this work is on the critical path for the *Digital Creativity* submission — the submission validates `brief` mode reconstruction, which is unaffected by all four decisions.

## What stays in v0.1 territory after these decisions

The following are explicitly *not* in scope for v0.2 under these decisions:

- **Runtime grounding for `lineage` mode** (Wikidata / ULAN / e-flux refuse-to-emit-on-low-confidence). `SKILL.md:176` defers this to v0.2; this decision document does not promote it into the v0.2 commit set. It remains a v0.3 candidate.
- **Persona-collapse measurement** (`commands/rehearsal.md:39` — "qualitative check at v0.1"). The honest qualitative check stays; the inter-persona-agreement measurement procedure named at `SKILL.md:131` (per audit Phase 2) is *not* operationalized here. Voice 2 wanted it; the synthesis declines for the same reason intent detection got promoted and Dialogue Health got demoted — pick the cadence rule that fires reliably, not the one that nags.
- **Drift-agent v0.2 rewrite.** Deferred to v0.3. The archive in (d) is the v0.2 commitment; the rewrite work is not.
- **PDF / DOCX export.** Per `.claude/CLAUDE.md` "Output: Markdown (default). PDF / DOCX export deferred to v0.2." This decision document does not pull export into v0.2 scope either; markdown remains the only output format.
- **Multi-user / collaborative project files.** The (b) persistence mechanism is single-user, single-machine-with-sync. Collaborative editing of `~/.art-project/projects/[codename]/project.md` is out of scope; conflict resolution if two machines edit the same file is the artist's problem (git resolves it).
- **SessionStart hook rename** (`scripts/announce-art-paper-loaded.sh`, per audit `:24`). Cosmetic; if it gets fixed alongside item 1 of the roadmap, fine, but it is not a v0.2 commitment.
- **Empirical validation of any mode other than `brief`.** Decisions (a) and (b) build mechanisms; they do not test them at scale. Empirical compliance for rehearsal-friction firing and full-mode persistence is v0.3 (or post-publication) work, after the *Digital Creativity* submission is in review.

## One-line decision summary

(a) build a minimal consultative log; (b) build minimal filesystem persistence; (c) operationalize intent detection as HARD, demote Dialogue Health out of the IRON registry; (d) archive the four drift agents in `agents/deprecated/`, rewrite deferred to v0.3.
